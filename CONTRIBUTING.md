# Contributing to Low Country Cyber Solutions Repositories

Use a focused feature branch and a signed commit for every change. Open a
draft pull request, describe the purpose and rollback, and run the repository's
documented validation before requesting review.

Do not commit credentials, tokens, private keys, environment files, Terraform
state or plans, customer data, raw evidence, exports, backups, databases,
installers, generated reports, or runtime logs.

Repository-specific `AGENTS.md`, `README`, build manifests, and validation
scripts remain authoritative. Live cloud, infrastructure, endpoint, customer,
email, or runtime mutations require separate explicit approval and do not
belong in ordinary validation workflows.
